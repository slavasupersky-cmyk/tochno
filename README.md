# ТОЧНО. Недвижимость

Одностраничный сайт агентства недвижимости. Статический, без фреймворков и без зависимостей — `index.html` собирается скриптом на чистом Node из одного файла с текстами.

## Быстрый старт

```bash
npm run build          # собрать dist/
npm run dev            # собрать и поднять http://localhost:8080
npm run texts:export   # выгрузить все тексты в TEXTS.md для правки
npm run texts:import   # вернуть правки из TEXTS.md и пересобрать
npm run images         # проверить, все ли картинки на месте
```

Node 18 или новее. Устанавливать ничего не нужно — зависимостей нет.

## Структура

```
src/
  content.json        ← ВСЕ ТЕКСТЫ САЙТА. Правится только этот файл.
  styles/style.css       стили, разложены по слоям @layer
  scripts/site.js        поведение: шапка, форма, появление блоков
  images/                7 фотографий, каждая в .jpg и .webp
  partials/              логотипы в SVG
build.js              сборка content.json → dist/index.html
texts.js              выгрузка и загрузка текстов через TEXTS.md
images.js             проверка комплектности картинок
dist/                 результат сборки, в git не попадает
```

## Как менять тексты

Два способа — оба ведут в один и тот же `src/content.json`.

**Через TEXTS.md — когда правит не разработчик.** `npm run texts:export` собирает все 136 текстовых блоков сайта в один markdown-файл с человеческими подписями. Правите текст, `npm run texts:import` раскладывает его обратно и пересобирает сайт.

В TEXTS.md под каждым заголовком стоит служебная строка вида `<!--hero.title|lines-->` — по ней импорт понимает, куда положить текст. Её трогать нельзя, остальное правится свободно. Если строка потеряется или текст под ней окажется пустым, импорт остановится и скажет, где именно, ничего не сломав.

Там, где под заголовком несколько строк, каждая строка — отдельный элемент: в заголовках это перенос строки, в списках — отдельный пункт.

**Напрямую в content.json — когда правит разработчик.** Меняете строку, `npm run build`, готово. HTML править вручную не нужно, он перезаписывается при каждой сборке.

Переносы строк в заголовках задаются массивом: `["Первая строка", "Вторая строка"]` превращается в `Первая строка<br>Вторая строка`.

Фрагмент заголовка в звёздочках красится акцентным цветом: `"Начните с разговора*.*"` даст зелёную точку в конце.

Всё содержимое экранируется при сборке, так что кавычки и угловые скобки в текстах безопасны.

## Типографика

В проекте ровно четыре размера шрифта для контента плюс один служебный для капслок-подписей. Новых размеров не заводим — если нужен акцент, берём вес или цвет.

| Токен | Размер | Где применяется |
|---|---|---|
| `--fs-display` | 38 → 76px | `h1`, заголовок первого экрана |
| `--fs-title` | 28 → 52px | `h2`, заголовки секций, пункты меню |
| `--fs-heading` | 19 → 24px | `h3`, названия карточек, вопросы FAQ, значения в контактах |
| `--fs-body` | 16px | весь основной текст, поля формы, кнопки |
| `--fs-label` | 12px | капслок-подписи, надзаголовки, чекбоксы |

## Архитектура CSS

Каскад зафиксирован через `@layer`, порядок задан в первой строке файла:

```
tokens → base → layout → components → utilities
```

Специфичность селекторов больше ни на что не влияет: правило из `components` всегда перебивает `layout`, независимо от того, как записано. `!important` в проекте нет.

Цветовая тема — набор смысловых токенов (`--c-ink`, `--c-paper`, `--c-accent` и т. д.). Тёмная тема переопределяет только значения токенов, не добавляя ни одного нового селектора. Тёмные секции внутри светлой страницы работают так же: класс `.on-night` подменяет те же токены для своего поддерева.

## Картинки

Каждая фотография лежит двумя файлами: `.webp` для современных браузеров и `.jpg` как фолбэк. Сборка расставляет их через `<picture>`, так что в `content.json` указывается путь **без расширения**:

```json
"image": { "src": "images/founder", "alt": "Основательница агентства" }
```

Первый экран грузится с `fetchpriority="high"`, остальное — лениво.

### Как заменить фотографию

Имена файлов фиксированы — положите новый файл поверх старого, ничего в коде менять не нужно.

| Файл | Ширина | Пропорция | Где показывается |
|---|---|---|---|
| `hero-apartment` | 1920px | горизонтальная, ~3:2 | первый экран во всю высоту окна; низ затемнён градиентом, там лежит текст |
| `service-buy` | 900px | **4:3** | карточка «Купить» |
| `service-sell` | 900px | **4:3** | карточка «Продать» |
| `service-invest` | 900px | **4:3** | карточка «Инвестировать» |
| `service-deal` | 900px | **4:3** | карточка «Провести сделку» |
| `analytics` | 1200px | вертикальная или квадрат | секция «Аналитика», половина ширины на десктопе |
| `founder` | 1000px | вертикальный портрет, ~4:5 | секция «Об агентстве» |

Карточки жёстко кадрируются в 4:3 через `object-fit: cover` — если дать другую пропорцию, края обрежутся по центру.

После замены сделайте WebP-версию и проверьте комплектность:

```bash
cwebp -q 80 src/images/hero-apartment.jpg -o src/images/hero-apartment.webp
npm run images
```

`npm run images` берёт список слотов из `content.json`, так что он не разъедется с сайтом: покажет, где не хватает файла, где нет WebP-версии и какие файлы в папке лежат зря.

Не забудьте поправить `alt` в `content.json` (или в TEXTS.md — они там есть) под новую картинку: это и доступность, и SEO.

## Деплой

`dist/` — обычная статика, кладётся куда угодно: GitHub Pages, Netlify, Vercel, nginx.

Перед публикацией:

- заменить `meta.url` в `content.json` на реальный домен;
- подключить отправку формы;
- заменить ссылку на политику конфиденциальности (`contacts.form.consents[0].linkHref`);
- проверить цифры, реквизиты и отзывы — см. дисклеймер в подвале.
